# PIXEL PLANNER — 8-битный ежедневник

Офлайн-PWA в стиле NES/аркадных автоматов: план дня, повторяющиеся задачи, бэклог («Инвентарь»),
привычки («Квесты»), статистика («Таблица рекордов»), XP/уровни/достижения и напоминания.
Все данные хранятся локально в IndexedDB.

## Стек
Vite 8 · React 19 · TypeScript (strict) · Zustand · Dexie 4 · CSS Modules + дизайн-токены ·
@dnd-kit · vite-plugin-pwa (свой service worker) · Vitest.

## Запуск
```bash
npm install
npm run dev        # http://localhost:5173
npm run lint
npm test
npm run build      # результат в dist/
npm run preview    # проверить собранную версию (service worker, офлайн)
```
Нужен Node.js 20+.

## Структура
```
src/
  domain/     чистая логика без React/БД: даты и DST, повторения, стрики, статистика,
              расчёт напоминаний, XP и достижения (+ тесты *.test.ts)
  data/       Dexie-схема, репозитории (единственная точка доступа к хранилищу),
              live-хуки, бэкап JSON, действия из уведомлений
  services/   сценарии: задачи/серии, привычки, начисление XP, 8-битный звук (WebAudio)
  sync/       синхронизация между устройствами: ядро (слияние по updatedAt) и менеджер (сеть, триггеры)
  stores/     Zustand: настройки, UI-состояние, игровые события
  features/   экраны: day, recurring, backlog, habits, stats, game, notifications, settings, pwa
  ui/         пиксельные примитивы и иконки 8×8 (битмапы → SVG)
  charts/     собственные SVG-графики с crispEdges
  styles/     tokens.css — вся палитра, base.css, crt.css
  sw/         service worker: precache + кнопки «Выполнено» / «Отложить» в уведомлениях
```

### Ключевые решения
- **Даты** хранятся как локальные `YYYY-MM-DD`, время — как «настенное» `HH:mm`. Календарная арифметика
  идёт через UTC-полночь, поэтому переход на летнее время и смена пояса не сдвигают повторы.
  Абсолютный момент считается только для уведомлений (`toInstant`): несуществующее время сдвигается
  вперёд, двойное — берётся первое.
- **Повторения**: хранится правило (`RecurringSeries`), экземпляры генерируются на лету; выполнение и правки
  конкретного дня — в `OccurrenceOverride`. «Эта и все следующие» делит серию на две.
  Прошедшие невыполненные экземпляры помечаются «пропущено» и не переносятся.
- **Синхронизация в будущем**: у каждой записи есть `updatedAt` и мягкое удаление `deletedAt`;
  UI работает только через репозитории (`src/data/repo.ts`) — бэкенд добавляется заменой реализации.
- **Палитра** — только в `src/styles/tokens.css`: один смысловой цвет на сущность
  (задачи — циан, привычки — зелёный, XP — жёлтый, предупреждения — маджента).

### Несколько напоминаний
В редакторе задачи (нужно указать время) кнопка «+ Напоминание» добавляет ещё одно поле: «в момент начала», за 5, 15, 30
или 60 минут. Можно задать до 5 напоминаний, одинаковые значения не предлагаются. Каждое приходит отдельным уведомлением
(в том числе push). У повторяющихся задач список общий для серии, а в режиме «только эта» можно задать свой на день.
Старые задачи с одним напоминанием работают без миграции: поле `reminder` читается наряду с новым `reminders`
(`src/domain/reminderSpecs.ts`).

### Метки
Метки — рабочий фильтр, а не украшение. «Работа» и «работа» — одна метка (всё приводится к нижнему регистру).
На экране дня над списком появляется панель меток этого дня со счётчиками: нажатие сужает список (несколько меток —
нужны все выбранные), «Сбросить» очищает фильтр. Пока фильтр включён, прогресс и кнопка «Выбранные на завтра» относятся
только к видимым задачам, а перетаскивание отключено (чтобы не сбить порядок скрытых). Метка под названием задачи
нажимается и включает тот же фильтр; в инвентаре — то же самое. Ссылка «Все дни и инвентарь →» открывает страницу
метки: просроченное, сегодня, впереди, инвентарь, повторяющиеся и недавно выполненное — всё с этой меткой. В редакторе
под полем меток предлагаются уже существующие метки, чтобы не плодить вариации. Логика — в `src/domain/tags.ts`.

### Быстрый ввод
Строка быстрого ввода закреплена внизу экрана дня поверх списка (на телефоне — над нижней навигацией): это поле со своей
кнопкой «Добавить» (можно нажать и её, и «Отправить» на клавиатуре), задача создаётся сразу, без окна, а курсор остаётся
в поле — можно вводить задачи подряд. Кнопка «Новая задача» в шапке панели, наоборот, открывает полный
редактор (дата, время, напоминания, заметки, чек-лист). Строка понимает обычный русский текст: «Позвонить маме завтра в 15:00 #семья !». Распознаются
**дата** (сегодня, завтра, послезавтра, в пятницу, через 3 дня / неделю / месяц, 15 ноября, 15.11), **время**
(в 15:00, в 9 утра, в 7 вечера, в 9), **приоритет** (`!`, `!высокий`, `!средний`, `!низкий`), **метки** (`#слово`),
**повтор** (каждый день, по будням, каждый понедельник, каждые 3 дня, каждую неделю, каждый месяц) и **напоминание**
(«напомни за 15 минут / за час», нужно время). Под строкой показывается, что именно распознано; нажатием на
распознанную часть её можно отключить — тогда она останется в названии как обычный текст. Логика — в
`src/domain/quickAdd.ts` (чистая функция, покрыта тестами).

### Заметки и чек-листы в задачах
В редакторе задачи блок «Добавить к задаче» включает **заметки**, **чек-лист** или оба сразу. Пункты чек-листа
добавляются клавишей Enter, их можно отмечать прямо в списке дня (прогресс «2/3», блок сворачивается). У повторяющихся
задач список пунктов общий, а отметки хранятся отдельно для каждого дня; в «только эта» можно задать свой список на день.
Отметка всех пунктов саму задачу не закрывает.
Заметки тоже видны под задачей в списке дня. Блоки «Заметки» и «Чек-лист» сворачиваются, состояние запоминается
на устройстве (у повторяющихся задач — одно на всю серию).

### Привычки со счётом
При создании квеста можно выбрать тип: **«Отметка»** (сделал / не сделал) или **«Со счётом»** — за каждый день
записывается число в выбранных единицах (отжимания, км, страницы…). У счётной привычки вводится число за сегодня,
любой день календаря можно заполнить или поправить задним числом, а по названию (или значку графика) открывается
экран с показателями (сегодня, среднее за 7 дней и динамика, лучший день, всего), пиксельным графиком за 14/30/90 дней
со скользящим средним и историей записей. День считается выполненным, если записано число больше нуля, — поэтому
стрики, XP и статистика работают так же, как у обычных привычек.

### Сворачивание привычек
У каждой карточки привычки есть кнопка «Свернуть» (в свёрнутом виде — «Календарь»): календарь месяца прячется, остаются
название, отметка или ввод числа за сегодня и стрики. Кнопка «Свернуть все / Развернуть все» вверху экрана
квестов. Состояние запоминается на устройстве.

### Синхронизация между устройствами
Настройки → «Синхронизация». На первом устройстве нажмите «Включить синхронизацию» — создастся случайный ключ
(43 символа) и покажется QR-код. На втором устройстве: «Подключиться по QR-коду» (камера) или вставьте ключ
вручную. Ключ работает как пароль и хранится только на устройствах (в таблице `meta`, в бэкап JSON не попадает).

Как работает: каждая запись (`tasks`, `series`, `overrides`, `habits`, `habitLogs`, `xp`, `achievements`) уходит на
сервер целиком, при расхождении побеждает больший `updatedAt`; удаления переносятся как записи с `deletedAt`.
Настройки и журнал напоминаний остаются своими на каждом устройстве. Устройство забирает с сервера только новое
(курсор `seq`) и отправляет только изменённое с прошлого раза. Проход запускается при открытии, возвращении в
приложение, появлении сети, раз в минуту и через 3 секунды после любой правки. Без сети всё работает офлайн.

Сервер (`/api/sync`, таблица D1 `sync_records`, миграция `0002_sync.sql`) видит только SHA-256 ключа и JSON записей;
данные на нём не шифруются. «Удалить данные с сервера» стирает всё по ключу. Перед первым использованием на
Cloudflare примените миграцию: `npm run deploy`.

### Окно «Что нового» и выпуск обновлений
После обновления при первом запуске показывается окно с патч-ноутами всех версий, которые пользователь ещё не видел
(не больше пяти; новичку, у которого ещё нет данных, окно не показывается). Историю можно открыть в
Настройках → «О приложении». Какая версия уже показана, хранится на устройстве (таблица `meta` в IndexedDB).

**Чтобы выпустить обновление с патч-ноутом:** добавьте запись в начало списка в `src/changelog.ts`
(версия, дата, заголовок, пункты) и поднимите `version` в `package.json` до той же версии — тест проверяет, что они
совпадают. Если запись не добавить, пользователи обновятся тихо, без окна.

### Горячие клавиши
`N` — новая задача/квест · `←/→` — день (месяц в квестах) · `T` — сегодня · `/` — поиск в инвентаре · `Esc` — закрыть.

### Уведомления (этап А)
Разрешение запрашивается только по кнопке в Настройках. Напоминания приходят, **пока приложение открыто
или живо в фоне**; сработавшие без вас показываются блоком «Пропущенные» при следующем открытии.
Для доставки при закрытом приложении нужен push-сервер (этап Б).

### Иконки PWA
Генерируются скриптом без зависимостей: `python3 scripts/make-icons.py`.

## Деплой

### GitHub Pages
Роутинг на hash-адресах, поэтому дополнительная настройка 404 не нужна. Сборка с базовым путём репозитория:
```bash
BASE_PATH=/<имя-репозитория>/ npm run build
```
Пример workflow `.github/workflows/deploy.yml`:
```yaml
name: Deploy
on: { push: { branches: [main] } }
permissions: { contents: read, pages: write, id-token: write }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci && npm run lint && npm test
      - run: npm run build
        env: { BASE_PATH: "/${{ github.event.repository.name }}/" }
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: { name: github-pages }
    steps:
      - uses: actions/deploy-pages@v4
```
В настройках репозитория: Settings → Pages → Source: **GitHub Actions**.

#### Текущая схема: сайт на GitHub Pages, push-API на Cloudflare
Сайт: https://vreremenko.github.io/pixel-planner/ — собирается workflow `.github/workflows/deploy.yml`
при каждом push в `main` (lint → тесты → сборка → Pages). Адрес push-API передаётся сборке через
переменную репозитория `API_BASE` (→ `VITE_API_BASE`), а воркер разрешает запросы с этого домена
через `ALLOWED_ORIGINS` в `wrangler.jsonc`. Так сайт открывается там, где Cloudflare недоступен
(push-запросы маленькие и проходят), а сами уведомления доставляют серверы Apple/Google.

### Vercel
Импортируйте репозиторий: Framework — Vite, Build — `npm run build`, Output — `dist`. `BASE_PATH` не нужен.

### Cloudflare Workers + Web Push (этап Б, текущий деплой)
Один бесплатный Cloudflare Worker раздаёт фронтенд (static assets), принимает API `/api/*`
и раз в минуту (Cron Trigger) рассылает наступившие напоминания через Web Push. Подписки и расписание
лежат в D1. Код — `server/src/index.ts`, схема — `server/migrations/`, конфиг — `wrangler.jsonc`.

Первый деплой:
```bash
npx wrangler login                         # вход в аккаунт Cloudflare (email должен быть подтверждён)
npx wrangler d1 create pixel-planner-push  # database_id → wrangler.jsonc
npm run vapid                              # пара ключей VAPID
# публичный ключ → wrangler.jsonc: vars.VAPID_PUBLIC_KEY
npx wrangler secret put VAPID_PRIVATE_KEY  # приватный ключ — только в секретах, не в коде
npm run deploy                             # сборка + миграции D1 + wrangler deploy
```
Повторные деплои — просто `npm run deploy`.

Локально с push-API: `npm run dev:api` (worker на :8787, ключи — в `.dev.vars`, он в .gitignore)
и параллельно `npm run dev` — Vite проксирует `/api` на воркер.

API: `GET /api/config`, `PUT|DELETE /api/devices/:id` (подписка), `PUT /api/devices/:id/schedule`
(расписание на 7 дней), `POST /api/devices/:id/snooze`. id устройства — случайный UUID, известный только ему.

Без сервера (GitHub Pages / Vercel) приложение работает полностью, но push-переключатель будет недоступен.
